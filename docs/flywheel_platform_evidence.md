# Flywheel Evidence Map

This is a lightweight progress report for platform additions that must show at
least one flywheel contribution before we add more machinery. Scores are rough:

- 0 = platform exists only as code
- 1 = mechanical smoke test
- 2 = transcript produces useful structured feedback
- 3 = live LLM responds to that feedback or prompt seed
- 4 = creates new accepted cases or robust sweep behavior

## 2026-07-14 Restart Assessment

The current architecture is stronger than the current native coverage. The
collaborative solver has a good protocol for LLM-tool communication, but it is
not yet natively ahead of the reference mechanical baseline. The next measurable
goal is to separate:

- native collaborative solver accepted cases;
- accepted cases that rely on the quarantined reference child fallback;
- load-bearing LLM wins where a hint/route changes failure into acceptance.

The latest high-signal false-side experiment is
`.artifacts/collab_after_false_guard_hard2_0027_fastllm.json`: live
`gpt-oss-120b` now follows false-side phase guidance and proposes concrete
`false_model_search` routes, but `hard2_0027` still fails. The sharper current
diagnostic has moved past the earlier `cp_sat:n=8` recommendation:
`.artifacts/hard2_0027_stoploss_model_finder_v2_n8.json` found no witness from
the LLM-suggested `model_finder_v2:n=8` continuation, and
`.artifacts/hard2_0027_stoploss_cp_sat_n9.json` left all canonical `cp_sat:n=9`
branches `UNKNOWN` under the bounded pass. This points to false-consumer
strength as the next bottleneck, but also puts `hard2_0027` in stop-loss status
until a new false-consumer mechanism or structured witness family exists.
